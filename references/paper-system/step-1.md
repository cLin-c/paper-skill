# 第1步 · 设计故事线

## 阶段任务与交付

这一步做什么：确定研究要解决什么重要问题、现有方法缺在哪里，以及准备提出什么可检验的核心主张。

1. 阅读代表性论文，梳理已有方法的能力、局限与尚未解决的核心难题。
2. 明确研究目标属于效果领先、能力突破，还是机理解释；确定比较对象与适用条件。
3. 形成“重要问题 → 现有缺口 → 核心洞察 → 方法 → 验证 → 贡献与边界”的故事线，并初步确定目标期刊或会议。

应产出的材料：一句话核心故事线、贡献草案、文献差距表、主张—实验对应表、目标刊会候选。

完成标准：每项拟议贡献都能提出验证方法；尚无实验支持的主张明确作为待验证假设。

## 1.1 投稿核心：讲好故事、做好证据

来源编号：`prompt-52`

```text
学术论文投稿的核心是讲好故事、做好证据。请围绕这两个核心，审查并完善我提供的论文和研究材料。

一、讲好故事
1. 用一句话说清：研究了什么重要问题，现有方法的关键缺口是什么，本文提出了什么核心思路，以及证据支持了什么结论。
2. 建立“重要问题—现有缺口—关键洞察—方法设计—证据验证—贡献与边界”的完整逻辑链。每一环都要回应上一环，避免堆砌技术模块或罗列实验。
3. 提炼有明确比较对象、可验证的核心贡献，并让标题、摘要、引言、方法、实验、讨论和结论围绕同一条主线展开。
4. 检查每个段落、图表和实验对主线的作用，指出跳跃、重复和偏离主题之处，给出具体修改建议。

二、做好证据
1. 建立“核心主张—对应证据—图表或章节位置—证据强度—缺失验证”的对照表。关键结论必须能追溯到真实数据、实验、理论推导或可靠文献。
2. 根据论文类型，检查公平对比、消融实验、统计不确定性、鲁棒性、泛化性、效率、失败案例及复现信息是否足以支撑主张；仅要求与研究问题相关的验证。
3. 区分相关性与因果性、观察结果与机制解释，以及已验证结论与待验证假设。证据不足时，提出最小必要补充实验，或收缩结论范围。
4. 检查正文、图表、摘要和结论中的数据、指标、比较条件及论断是否一致，明确适用条件与局限。

请依次输出：一句话主线、故事线提纲、主张与证据对照表、按优先级排序的证据缺口及补充方案、可直接采用的修改建议。

讲好故事必须以真实研究为基础，不夸大创新，不编造数据、实验或参考文献，不隐瞒不利结果，也不承诺录用。区分已核实（VERIFIED）、未核实（UNVERIFIED）和需作者补充（AUTHOR_INPUT_NEEDED）的内容。
```

## 1.2 单篇论文精读

来源编号：`prompt-1`

```text
请你仔细阅读我上传的论文，并按照以下结构进行分析：
1. 论文研究问题：作者要解决什么核心问题？
2. 方法框架：论文提出了什么方法？关键模块分别是什么？
3. 创新点：相较已有工作，真正的新意在哪里？
4. 实验设计：做了哪些实验？每个实验验证什么？
5. 实验结果：主要结果、对比结果和消融结果说明了什么？
6. 应用场景：该方法适合哪些实际场景？有什么限制？
7. 可复现性：实现该工作的关键条件、数据、设备、算法流程是什么？
8. 对我研究的启发：哪些思路可以借鉴到我的课题中？

要求：回答要具体，不要泛泛而谈；如果论文中存在逻辑不清、实验不足或创新性不足的问题，也请指出。
```

## 1.6 创新定位与核心故事线重构

来源编号：`prompt-41`

```text
请在不改变论文题目、方法名称、技术路线和实验事实的前提下，强化论文的创新定位与核心故事线。

先提炼：应用挑战 → 共性科学问题 → 现有方法根本限制 → 本文统一机制 → 理论依据 → 实验验证 → 任务价值。

随后检查摘要、引言、相关工作、贡献、方法开头、实验分析和结论，确保：
1. 每个高层术语都有真实机制、公式或实验支撑；
2. 不把模块组合、参数调整和工程集成包装成理论创新；
3. 不堆砌“自主、智能、统一、通用、鲁棒、泛化”等空洞词；
4. 现有证据支持的结论直接、准确地陈述，压缩“不能代表、不用于、不应理解为、仅能说明”等防御性表达；
5. 每项贡献明确回答“提出了什么、解决了什么、为何有效、证据是什么”。

输出修改后的完整文本，并附术语升级表和主张—机制—证据矩阵。

投稿核心原则：讲好故事、做好证据。
请在本任务中检查“重要问题—现有缺口—关键洞察—方法—验证—贡献与边界”的主线是否连贯，并逐项对应核心主张及其真实证据。指出故事线断点、证据缺口和过度推断；给出具体修改或最小必要补充验证方案。没有证据支撑的结论应收缩或标为待验证，不得通过夸大表述、编造数据或隐瞒不利结果增强说服力。
```
